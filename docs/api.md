# The Plugin's API

Under `/api/plugins/splatme/`, with a WebODM login. A POST or PUT also needs the session's CSRF token (`X-CSRFToken`), as
WebODM routes a plugin's API through a plain Django view.

| Request | Does |
|---|---|
| `GET nodes` | Every splat node set up, the default first: its `id`, `name`, state (`node`, as `GET node` gives it) and `trainer_kind`, or `error`; for administrators also its `url`, `token_set` and `named` (false: named after its trainer, as `GET nodes` renames it once the node answers). Tokens are never sent back |
| `POST nodes` (`name`, `url`, `token`, `save`) | Superusers: adds a node (its id in `saved`, with the list; with no `name`, named after its trainer); with `save` false only tries the address and token (`tried`: the state, or what is wrong) |
| `POST nodes/<id>` (`name`, `url`, `token`, `save`, `default`) | Superusers: changes a node (an empty token keeps the one set, an empty name names it after its trainer), tries it with `save` false, or with `default` true makes it the default (the first) |
| `DELETE nodes/<id>` | Superusers: removes a node from SplatMe (the node itself keeps running); refused while a training is under way on it |
| `GET node` | The default node's state or that it is not available (with `update`: what an older node lacks, or null), and its `url`; for administrators also what is wrong and `token_set`. The token is never sent back |
| `POST node` (`url`, `token`, `save`) | Administrators: sets the default node's address and token; with `save` false only tries them |
| `GET task/<id>/check` | Before training: why the task or the node cannot train, warnings, the options' ranges, `boundary` (whether the task was processed with one), `thermal` (whether its photos are DJI Thermal Analyzer's TIFFs), `photo_sizes` (the photos' `[width, height]`, one per camera, empty before processing), `trained_steps`: the steps of the model a training can continue from, `trained_kind`: the trainer that made it (`opensplat` when not known), `trained_grow_until`: that model's `densify_until`, when it was set, `nodes`: every node set up (`id`, `name`, `trainer_kind`, `error`, and `continue_problem`: why it can't continue the task's model, or null), and `node`: the trainer of the node chosen with `?node=<id>` (the default without it; `node_id` names it): `trainer_kind`, `supports`: `masks` and `continue`, and `ranges`, the range of each option it has; null when that node does not answer |
| `POST task/<id>/train` | Trains a completed task's splats. Options: `steps` (30000), `image_size` (1600, the photos' longer side in pixels, larger photos scaled down whole; 0 keeps them as they are), `max_gaussians`, `sh_degree`, `densify_until` (Grow Until: from 1,000 to `steps` - 3,000; blank, half the steps, at most 15,000), `strategy` (one of the node's choices) and `exposure_correction` (true or false) for a LichtFeld Studio node; an option the node's trainer lacks is left out and named in the job's `skipped`, `ignore_sky` (true leaves the sky out; not for a thermal task), `crop` (false keeps the splats outside the task's boundary), `palette` (a thermal task's colours: `gray`, the default, `gray_r`, `iron`, `magma`, `inferno`, `plasma`, `viridis`, `cividis`, `jet`). `node` (a node's `id`; the default without it). With `resume` true it continues the task's trained model, on any node whose trainer can read the model's data (`check`'s `continue_problem`): `steps` is then how many more, `densify_until` (optional) from the model's steps + 1,000 to the new total - 3,000, and the other options are the ones that model was trained with (only those the node's trainer has, when another trainer made it) |
| `GET task/<id>/status` | The job's `state`, `progress`, `status`, `error`, `sky_masks` (in how many photos sky was found, with `ignore_sky`), `cropped` (the gaussians left out for being outside the boundary), `thermal` (a thermal task's `palette` and the range it spans, `low` and `high`, in degrees Celsius), `time_left` (while training, the seconds the steps left should take, once known), `edited` (the gaussians the task's edits removed), `edits_error` (why they were not applied), `times` (the seconds spent in each state: `training` is the trainer's; earlier records have none), `resume` (the steps a continued training started from), `skipped` (the options it left out, as the node's trainer does not have them) and `earlier_training` (the trainer's seconds for the model continued from, null when not known), `thumbnail` (when the task's thumbnail was saved, null without one), whether the task has a splat model, whether it can be edited (`editable`), its last splat update (**Update the Model**) (`apply`), whether its textured model can be edited (`model_editable`) and its last update (`model_apply`) and whether the user may train it; for a task set to train, `listening` (whether WebODM's worker tells the plugin of completed tasks). With `?listed=1` also `listed`, whether SplatMe → Tasks lists the task, and `unlisted`, why not |
| `POST task/<id>/cancel` | Stops the job |
| `GET task/<id>/edits` | The task's splat edits (`edits`: boxes, polygons, lassos, brushes, floaters and a colour adjust, in its trained model's coordinates; `unreadable`: why saved edits could not be read, left as they are), the task's `name` and `project`, `editable` (why it cannot be edited, or null), `can_edit`, `training` (whether its splats train now), `apply` (its last splat update (**Update the Model**): `state`, `status`, `error`, `cropped`, `edited`) and `applied` (whether the task's model was made with the saved edits; null when not known). For those who may change the project, also `model` (the trained model's `url`, `size` and `splats`) and `boundary` (the rings Crop to Boundary leaves out, empty without it) |
| `PUT task/<id>/edits` (`edits`) | Replaces the task's edits, then answers as GET does; 400 when the task cannot be edited. A box is `{"type": "box", "keep": true, "center": [x, y, z], "size": [x, y, z], "turn": degrees}`; a polygon `{"type": "polygon", "keep": false, "ring": [[x, y], ...]}`; a lasso `{"type": "lasso", "keep": false, "ring": [[x, y], ...], "view": [16 numbers], "camera": {"position": [x, y, z], "target": [x, y, z]}}`, its ring on the screen (-1 to 1) and `view` the camera's view-projection matrix (column-major), keeping or removing (`keep`, as a box's) what is in front of the camera and inside the ring; a brush `{"type": "brush", "strokes": [{"size": 0.1, "points": [[x, y], ...]}, ...], "aspect": width / height, "view": [16 numbers], "camera": {...}}`, its points on the screen as a lasso's and `size` in half the screen's height, removing what is in front of the camera within `size` of a stroke's line (x times `aspect` first), or with `"restore": true` putting back what the edits before it removed; floaters `{"type": "floaters", "strength": "medium"}` (`light`, `medium` or `strong`, at most one), removing the gaussians far from their neighbours or oversized; a colour adjust `{"type": "colour", "brightness": 0.2, "contrast": 0, "saturation": -0.1, "warmth": 0}` (each -1 to 1, 0 for no change, at most one), changing every gaussian's colours. The edits apply in the list's order. At most 200 edits, 2,000 corners each, and 500 strokes and 20,000 points in a brush |
| `GET task/<id>/model` | The task's trained model as the trainer wrote it, before the boundary and the edits (a `.ply`), for those who may change the project |
| `GET task/<id>/floaters?strength=` | Which gaussians of the task's trained model are floaters at that strength: `removed`, their numbers in the trained model's file; for those who may change the project |
| `POST task/<id>/apply` | Makes the task's splat model again from its trained model and its edits; answers as `status`, whose `apply` follows it. With `cancel` true it stops a running update instead, leaving the task's model as it was (`apply`'s `state` then `canceled`) |
| `GET task/<id>/thumbnail` | A JPEG of the task's model, taken by Edit Splats; 404 without one |
| `PUT task/<id>/thumbnail` | Keeps the JPEG in the request's body (`Content-Type: image/jpeg`, at most 200 kB and 1,024 pixels a side) as the task's thumbnail; answers `thumbnail`, its new version. Needs the right to change the project |
| `GET task/<id>/download` | The task's model with its saved edits, made as **Update the Model** makes it, as a `.ply` file (an attachment); a model that cannot be made answers 400 with the reason as plain text |
| `GET task/<id>/model-edits` | The task's textured model's edits (`edits`, in the model's local frame: the GLB's, less its `CESIUM_RTC`; `unreadable`: why saved edits could not be read), the task's `name` and `project`, `editable` (why the model cannot be edited, or null), `can_edit`, `apply` (its last update: `state`, `status`, `error`, `removed`, `flattened`, `moved`, `filled`, `added`, `cloned`, `triangles`) and `applied` (whether the model was made with the saved edits; null when not known); for those who may change the project, also `model` (the original GLB's `url` and `size`) |
| `PUT task/<id>/model-edits` (`edits`) | Replaces the model's edits, then answers as GET does. A shape is one of `edits`' (box, polygon, lasso or brush) with `op`: `delete` (keep or remove, or a brush's restore), `object` (Remove Object, a polygon or lasso only: what it marks that stands above the surface round it removed, the surface under it too, and that laid again) or `move` (with `offset` `[x, y, z]` metres, -100 to 100, `scale` `[x, y, z]`, 0.1 to 10, about the covered vertices' middle, and `soft`, 0 to 20 m: the move fading to nothing that far around). The Brush's strokes are `{"type": "paint", "op": op, "strokes": [...]}`, each stroke `{"points": [[x, y, z], ...], "radius": m, "view": [x, y, z]}` (radius 0.01 to 10 m, `view` the direction looked in), with `op` one of `delete`, `restore`, `fill`, `smooth` (with `passes`, 1 to 100), `flatten`, `raise` (with `amount`, -1 to 1 m), `clone` (with `source`, `target` (where the copy starts) and `normal` `[x, y, z]`, and `feather`, 0 to 5 m) or `object` (Remove Object, as a shape's: what the strokes mark, seen along `view`, and what stands on it there): the triangles within the radius of a stroke's path that face `view`; a fill or clone fills the holes whose whole rim is within the radius; a clone copies from `source` plus each place's offset from `target`, after the other edits. Straighten is `{"type": "straighten", "points": [[x, y, z], ...], "strength": 0 to 1, "reach": 0.01 to 20 m, "soft": 0 to 20 m, "lift": [start, end]}` (2 to 200 points, an edge traced as it is; `lift`, -20 to 20 m each, raises the straight line's first and last ends, `[0, 0]` when left out): the traced line moved onto the straight line between its first and last points, each place to the place as far along it, and the surface within `reach` of it moved as its nearest place, fading to nothing over `soft` past it; `strength` of the way. Also `{"type": "floating", "size": n}` (the pieces of fewer than n triangles, 1 to 100,000, but the largest) and `{"type": "holes", "size": n}` (the holes of at most n edges, 1 to 5,000). In the list's order, at most 200 |
| `GET task/<id>/model-original` | The textured model's original GLB, before any update; for those who may change the project |
| `POST task/<id>/model-apply` | Makes the task's textured model (GLB, OBJ and MTL) again from its originals with its edits; answers `apply` and `applied`. With `cancel` true it stops a running update instead |
| `GET task/<id>/log?offset=<bytes>` | The trainer's output from that byte on; the offset to ask from next is in the `X-Log-Offset` header |
| `GET task/<id>/auto` | Whether the task is trained when it completes, on which `node` (null: the default), with which `options` and each trainer's own (`by_kind`) |
| `POST task/<id>/auto` | Sets that for the task: `enabled`, `node`, `trainer_kind` (as for `automation`) and the options of `train`. When the task completes, the node that trains it uses its trainer's options; a node removed since is replaced by the default |
| `GET automation` | The setting SplatMe's panel starts with for the user's new task: their own (`own` true) or the administrators' defaults: its `node` (null: the default), `options` (those last saved) and `by_kind` (each trainer's own options, by `trainer_kind`), and `listening`, whether WebODM's worker tells the plugin of completed tasks. With `?ranges=1` also a node's range of each option and its trainer (`trainer`, as `check`'s `node`): the node of `?node=<id>`, else the setting's |
| `POST automation` (`node`, options) | Saves the user's own options, as the chosen node's trainer's (or, when the node does not answer, `trainer_kind`'s), beside the other trainer's; with `reset` true drops them |
| `GET automation/shared`, `POST automation/shared` (options) | The administrators' defaults, for users who saved none of their own (`?ranges=1` as above); superusers set them |
| `GET revive` | Takes over the trainings that lost their worker (WebODM's pages ask it); answers 204 |
| `GET tasks` | The tasks SplatMe can train in the projects the user may see (`?project=<id>` for one), by project (a project with none is left out), each with WebODM's `status`, `running_progress` and `last_error`, and its `splats` as `task/<id>/status` gives them; and `addable`, the projects the user may add a task to: SplatMe's Tasks page, in one request |
