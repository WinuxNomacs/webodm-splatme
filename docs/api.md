# The Plugin's API

Under `/api/plugins/splatme/`, with a WebODM login. A POST or PUT also needs the session's CSRF token (`X-CSRFToken`), as
WebODM routes a plugin's API through a plain Django view.

| Request | Does |
|---|---|
| `GET node` | The node's state or that it is not available, and its `url`; for administrators also what is wrong and `token_set`. The token is never sent back |
| `POST node` (`url`, `token`, `save`) | Administrators: sets the address and token; with `save` false only tries them |
| `GET task/<id>/check` | Before training: why the task or the node cannot train, warnings, the options' ranges, `boundary` (whether the task was processed with one), `thermal` (whether its photos are DJI Thermal Analyzer's TIFFs), `photo_sizes` (the photos' `[width, height]`, one per camera, empty before processing) and `trained_steps`: the steps of the model a training can continue from |
| `POST task/<id>/train` | Trains a completed task's splats. Options: `steps` (30000), `image_size` (1600, the photos' longer side in pixels, larger photos scaled down whole; 0 keeps them as they are), `max_gaussians`, `sh_degree`, `ignore_sky` (true leaves the sky out; not for a thermal task), `crop` (false keeps the splats outside the task's boundary), `palette` (a thermal task's colours: `gray`, the default, `gray_r`, `iron`, `magma`, `inferno`, `plasma`, `viridis`, `cividis`, `jet`). With `resume` true it continues the task's trained model: `steps` is then how many more, and the other options are the ones that model was trained with |
| `GET task/<id>/status` | The job's `state`, `progress`, `status`, `error`, `sky_masks` (in how many photos sky was found, with `ignore_sky`), `cropped` (the gaussians left out for being outside the boundary), `thermal` (a thermal task's `palette` and the range it spans, `low` and `high`, in degrees Celsius), `time_left` (while training, the seconds the steps left should take, once known), `edited` (the gaussians the task's edits removed) and `edits_error` (why they were not applied), whether the task has a splat model, whether it can be edited (`editable`), its last Apply Edits (`apply`) and whether the user may train it; for a task set to train, `listening` (whether WebODM's worker tells the plugin of completed tasks). With `?listed=1` also `listed`, whether SplatMe → Tasks lists the task, and `unlisted`, why not |
| `POST task/<id>/cancel` | Stops the job |
| `GET task/<id>/edits` | The task's splat edits (`edits`: boxes, polygons, lassos, brushes, floaters and a colour adjust, in its trained model's coordinates; `unreadable`: why saved edits could not be read, left as they are), `editable` (why it cannot be edited, or null), `can_edit`, `training` (whether its splats train now), `apply` (its last Apply Edits: `state`, `status`, `error`, `cropped`, `edited`) and `model`: the trained model's `url`, `size` and `splats` |
| `PUT task/<id>/edits` (`edits`) | Replaces the task's edits, then answers as GET does. A box is `{"type": "box", "keep": true, "center": [x, y, z], "size": [x, y, z], "turn": degrees}`; a polygon `{"type": "polygon", "keep": false, "ring": [[x, y], ...]}`; a lasso `{"type": "lasso", "keep": false, "ring": [[x, y], ...], "view": [16 numbers], "camera": {"position": [x, y, z], "target": [x, y, z]}}`, its ring on the screen (-1 to 1) and `view` the camera's view-projection matrix (column-major), removing what is in front of the camera and inside the ring; a brush `{"type": "brush", "strokes": [{"size": 0.1, "points": [[x, y], ...]}, ...], "aspect": width / height, "view": [16 numbers], "camera": {...}}`, its points on the screen as a lasso's and `size` in half the screen's height, removing what is in front of the camera within `size` of a stroke's line (x times `aspect` first), or with `"restore": true` putting back what the edits before it removed; floaters `{"type": "floaters", "strength": "medium"}` (`light`, `medium` or `strong`, at most one), removing the gaussians far from their neighbours or oversized; a colour adjust `{"type": "colour", "brightness": 0.2, "contrast": 0, "saturation": -0.1, "warmth": 0}` (each -1 to 1, 0 for no change, at most one), changing every gaussian's colours. The edits apply in the list's order. At most 200 edits, 2,000 corners each, and 500 strokes and 20,000 points in a brush |
| `GET task/<id>/floaters?strength=` | Which gaussians of the task's trained model are floaters at that strength: `removed`, their numbers in the trained model's file |
| `POST task/<id>/apply` | Makes the task's splat model again from its trained model and its edits; answers as `status`, whose `apply` follows it |
| `GET task/<id>/download` | The task's model with its saved edits, made as Apply makes it, as a `.ply` file (an attachment); a model that cannot be made answers 400 with the reason as plain text |
| `GET task/<id>/log?offset=<bytes>` | The trainer's output from that byte on; the offset to ask from next is in the `X-Log-Offset` header |
| `GET task/<id>/auto` | Whether the task is trained when it completes, with which options |
| `POST task/<id>/auto` | Sets that for the task: `enabled` and the options of `train` |
| `GET automation` | The options SplatMe's panel starts with for the user's new task: their own (`own` true) or the administrators' defaults, and `listening`, whether WebODM's worker tells the plugin of completed tasks. With `?ranges=1` also the node's range of each option |
| `POST automation` (options) | Saves the user's own options; with `reset` true drops them |
| `GET automation/shared`, `POST automation/shared` (options) | The administrators' defaults, for users who saved none of their own; superusers set them |
| `GET revive` | Takes over the trainings that lost their worker (WebODM's pages ask it); answers 204 |
| `GET tasks` | The tasks SplatMe can train in the projects the user may see (`?project=<id>` for one), by project (a project with none is left out), each with WebODM's `status`, `running_progress` and `last_error`, and its `splats` as `task/<id>/status` gives them; and `addable`, the projects the user may add a task to: SplatMe's Tasks page, in one request |
